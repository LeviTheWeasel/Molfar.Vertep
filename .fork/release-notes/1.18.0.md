# 🖼️ Molfar Vertep 1.18.0

A small engine release: apps can now ask for the **shape** of a picture. **Order:** get this engine release and restart. Social and Roleplay arrive as app updates (Updates dialog, press Update) and do not need it, but Social's wide place pictures only take effect with it.

## 🖼️ Pictures in the shape an app asks for
Until now `POST /v1/images` took only a prompt and a model, so a model drew whatever shape it liked, mostly square. An app can now add `aspect`: `"square"`, `"wide"` or `"tall"`. Social uses it for the pictures of City places and districts, which are shown wide.
- **ComfyUI and AUTOMATIC1111/Forge** keep the pixel budget you set for the server in Settings > Images and change only the proportions (1024 x 1024 becomes 1344 x 768 for a wide picture). Without a shape the server's own size is used, as before.
- **OpenAI-compatible servers** get the sizes the `gpt-image` and `dall-e-3` models list. Any other model gets the reshaped budget, and if the server refuses that size the picture is asked for again once with your own size, so a shape never turns a picture into an error.
- **NanoGPT** gets the model's listed size nearest to the shape; **Gemini** gets the aspect ratio.
- Models reached through the built-in catalog and OpenRouter's image endpoint cannot take a shape; they draw their own, as before. A value the engine does not know is ignored, never an error.

## 📦 What arrives through app updates
- **Social 0.18.1 to 0.21.0:** pictures and an isometric drawing for the City, friends-only Journal posts, a facts ledger beside each chat's memory note (a Facts page, pinned messages, "Remembered" under a reply), privacy as a rule of the program (the forum and clubs read only public facts, never the note, with a switch in Settings > Messenger), and a fix for the pictures on the relationship map.
- **Roleplay 4.139.0:** sprite windows (up to eight characters on screen, three placements, a "Visible part" slider).
Press Update in the Updates dialog to get them.

## Other changes
- A known gap, not fixed here: an app's SVG `<image>` with an engine picture stays broken because the app bridge rewrites picture addresses only in `src` (issue #460); Social works around it.
- Developer handbook pages for the Social changes of this period.

## How to get it
From source: `git pull && bun install && (cd client-agent && bun install) && bun run build:client`, then restart. Downloads and the Android APK are on this release page. See [CHANGELOG.md](https://github.com/MolfarWav/Molfar.Vertep/blob/main/CHANGELOG.md).
